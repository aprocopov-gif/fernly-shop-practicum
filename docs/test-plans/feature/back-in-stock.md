# Test plan: feature/back-in-stock

## Summary

Browse cards warn when only a few plants are left (`Only N left` for stock 1–3). At stock 0 the card keeps the existing **Out of stock** overlay and must never show **Only 0 left**. The badge sits with the other tags under the name and must not cover the photo or the save button. An out-of-stock plant page offers **Email me when it's back** / **Notify me** with no account required; in-stock plants hide the form and the API refuses them (`in_stock`). Emails must be full addresses (`name@example.com`; `a@b` and `name@` refused). One sign-up per email per plant, ignoring case, with refusal **"You're already on the list"** (`already_subscribed`). After success the page confirms which address will be emailed. New surface: `POST /api/plants/{plantId}/notify` → 201 `NotifyResult`. Expectations below are the documented ones: a failure against the app is a possible finding, not a reason to change the assertion. Code comments that say the feature needs no testing are ignored — the oracle is `docs/features/back-in-stock.md`, `docs/PRODUCT.md`, and the OpenAPI text this change registers. Nothing in `package.json` or config changed, so this plan does not schedule a full-suite run. This plan is not approved. Rows Q1–Q4 stay unresolved (`assumed — ask`) and get no test until a human resolves them.
