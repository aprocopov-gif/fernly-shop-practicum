# Test plan: feature/plant-reviews

## Summary

Plant pages gain a **Reviews** section: average (one decimal, halves up — ratings 5, 4 and 5 → **4.7**), count, and reviews newest first; empty plants invite the first review. Signed-in customers get **Write a review** (1–5 stars + 10–500 characters); everyone else sees sign-in to write. Stars must work as a keyboard radio group. After posting, the review appears immediately and the page thanks the customer. One review per customer per plant (`already_reviewed`). Only the author can delete; anyone else gets **Review not found**. New routes: `GET/POST /api/plants/{plantId}/reviews`, `DELETE /api/reviews/{reviewId}`. Expectations below are the documented ones: a failure against the app is a possible finding, not a reason to change the assertion. Code comments that say the feature needs no testing are ignored — the oracle is `docs/features/plant-reviews.md`, `docs/PRODUCT.md`, and the OpenAPI text this change registers. CSS modules and `docs/features/plant-reviews.md` are covered by these rows. Nothing in `package.json` or config changed, so this plan does not schedule a full-suite run. This plan is not approved. Rows Q1–Q5 stay unresolved (`assumed — ask`) and get no test until a human resolves them.
